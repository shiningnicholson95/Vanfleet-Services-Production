## 1. Deploy pipeline setup and fixes

**Goal:** Get `vanfleet-wp-theme/` into this new repo so file changes can be pushed and deployed to production via SFTP, and fix the existing `deploy.yml`.

- Pulled the theme **directly from production** via a new manual `pull-theme.yml` workflow (`workflow_dispatch`, SFTP mirror pull into a review branch) — not from an old local copy, after confirming the old local copy was stale/wrong content.
- Fixed real bugs in the original `deploy.yml`:
  - Trigger fired on **every** push to `main`, not just theme changes — added a `paths: ['vanfleet-wp-theme/**']` filter.
  - No guard against mirroring an **empty** local folder — `mirror --reverse --delete` against an empty `vanfleet-wp-theme/` would have wiped the live theme. Added a pre-flight check that aborts if the folder is empty.
  - `lftp` was passing credentials embedded in the `sftp://user:pass@host` URL (breaks on special characters) — switched to `-u user,pass -p port` flags.
  - A **quoting bug** (`\"/$REMOTE_PATH/\"`) left a literal stray `"` character in the path lftp received, causing it to misresolve as a relative path against its login cwd instead of the intended absolute path. Root-caused via the actual `lftp` error output, not guessed — fixed by dropping the unnecessary quoting (path has no spaces).
- Added `THEME_REMOTE_PATH` as a single GitHub repo variable shared by both workflows, instead of hardcoding the remote path twice.

**Precaution:** Verified the pull → commit → deploy round-trip was byte-identical (pulled content pushed straight back) before ever touching content, so the first live deploy through the new pipeline was a verified no-op, not a blind first run.
